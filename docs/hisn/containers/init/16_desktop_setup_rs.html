setup_desktop() — أكثر setup_*() تعقيداً. يُعيد ثلاثة قيم: (init_desktop_ep, launch_ep_cap, success).

خريطة CNode الـ Desktop بعد الإعداد:

  • Slot 0: Endpoint الـ Desktop الخاص (يُستمع عليه من init لإرسال رسائل)
  • Slot 1: launch_ep_cap — Endpoint يُرسل عليه Desktop طلبات تشغيل التطبيقات (يستمع عليه init)
  • Slot 2: نسخة من FS_Vault Endpoint
  • Slot 3: نسخة من Auth_Vault Endpoint

تسلسل الإعداد الفريد:

  1. إنشاء الكائنات القياسية (CNode, TCB, VSpace, IPC Page)
  2. إنشاء Endpoint ثانٍ (launch_ep) في Init's CNode — هذا الـ EP يُعطى لـ Desktop لترسل عليه، بينما init يستمع عليه
  3. تحميل ELF عبر ContainerLoader (Scratch: 0xC00000)
  4. read_fb_phys_addr(): يقرأ Extra Boot Info (header id=4) من Multiboot2 للحصول على العنوان الفيزيائي للـ Framebuffer الفعلي (VESA/bochs-display) وأبعاده
  5. fb_mapping::map_framebuffer_into_vspace(): يربط صفحات الـ Framebuffer في VSpace الـ Desktop عند 0x1000_0000
  6. ipc_send::send_framebuffer_info(): يُرسل رسالة IPC تحتوي: fb_vaddr, width, height, pitch, launch_slot, fs_slot, bpp

القرار التصميمي: Desktop لا تعرف العنوان الفيزيائي للـ Framebuffer — تعمل فقط مع العنوان الافتراضي (Virtual) الذي تُخبرها به init عبر IPC.
