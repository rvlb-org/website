**التصنيف:** Kernel / Memory Management / Bug Fix

تم اكتشاف وحل باغ معماري عميق في `ContainerLoader` يؤثر على تحميل أي حاوية ثانية في النظام. المشكلة كانت أن الـ loader يستخدم عنوان scratch ثابت (`0x800000`) في VSpace الخاص بـ init لنسخ بيانات ELF، مما يُسبب فشل الـ `seL4_X86_PageTable_Map` عند محاولة تحميل حاوية ثانية لأن هذا العنوان يكون محجوزاً بالفعل من التحميل الأول. الحل تمثّل في إضافة حقل `scratch_vaddr` كمعامل منفصل لكل `ContainerLoader`، مما يتيح لكل حاوية عنوان scratch خاص بها لا يتعارض مع غيرها (`0x800000` لـ crypto_vault، `0xA00000` لـ Tor)، مع دعم إنشاء PDPT/PD جديدة تلقائياً إذا كانت المنطقة خارج التغطية الحالية.
